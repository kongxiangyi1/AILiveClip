# 架构建议详述：升级五段式 + segmenter.py「切点自动吸附静音边界」

> 状态：建议待评审（未执行）
> 对象：E:\Clipping\opencode（当前三段式版本）
> 参考：E:\live-clip-tool 五段式实现（技术方案 v2.0/v2.1 + `src/semantic/segmenter.py`）
> 起因：known-issues.md 「附」结论——段04 话题不完整源于「AI 直出无兜底」，三段式缺少自动化静音吸附

---

## 1. 背景与动因

### 1.1 当前的痛点（三段式实测暴露）

| 场景 | 三段式现状 | 后果 |
|------|-----------|------|
| AI 手工选边界 | 全凭对话中阅读 transcript.json 直觉判断，肉眼不易找静音位置 | 段04 案例：边界选在 599500ms，把「牛奶自嘲」话题切没了 |
| 边界精度 | 直接落在句尾，不验证是否撞字 | 可能截断半句话，成片开头/结尾不干净 |
| 兜底机制 | 无（检错只靠人工在 Streamlit 里逐个复核） | 长直播切片逐段人工核对成本高 |
| 可复现性 | 边界逻辑全部藏在对话里，重跑/换人结果不稳定 | 无法自动化批量处理 |

### 1.2 五段式的目标

把「AI 只做语义判断、脚本做确定性优化」的边界画得更清楚：
**语义边界由 AI 定，物理切点由脚本吸附到停顿并加 margin**。规则决定、可测试、可复现。

### 1.3 参考现成实现

E:\live-clip-tool（五段式）已实现相同机制并完成 21/21 单测，本建议可直接参考其边界精修逻辑，无需从零设计。

## 2. 五段式架构全貌（对比三段式）

```
三段式（现状）                    五段式（目标）
━━━━━━━━━━━━━━━                  ━━━━━━━━━━━━━━━━━━━━━━━
阶段1 脚本: 音轨+转写             阶段1 脚本: 音轨+转写        → transcript.json
阶段2 AI:   阅读→分段→标题        阶段2 AI:   阅读→分段→标题    → segments.json（草案）
        ↕ (无兜底)                阶段3 脚本: 语义块→变点→合并  → clips_raw
阶段3 脚本: 切割+封面             阶段4 脚本: 静音吸附+margin   → clips_refined.json
                                 阶段5 脚本: 切割+封面          → output/
```

**核心差异**：把原来「AI 一次直出最终边界」拆成两步——
- **AI 产出语义意图**（哪里话题变化 → 候选边界）
- **脚本用静音数据把候选边界精修成物理安全切点**

这样 AI 不必手工找静音，脚本也不必做语义判断，各司其职。这就是「切点自动吸附静音边界」机制的由来。

---

## 3. 各阶段职责（重点：阶段3/4 = segmenter.py）

### 阶段1（现有 asr_pipeline.py，不变）
产出 `transcript.json`：sentences + silences（当前结果已含静音段，见 asr_pipeline.py 的 `all_silences`）。

### 阶段2：AI 语义切分（分段职责，工作方式变）
- 通读全部句子，给出**话题分段**：哪些句群属于同一话题、边界在哪句话附近。
- 输出新增字段：`boundary_hint_ms`（话题边界期望位置，如边界句 end_ms）——**只表达"该处要切"，不要求精确到静音**。
- 保留现有规则：宁大勿碎、时长兜底（<45s 并入、>10min 拆分）、过渡句归后段、标题生成。

### 阶段3：语义块组装（脚本，把 sentences 变成"块"）
- 供依赖：以 ≥1.2s 停顿 + 句边界把句子组装成 `语义块`（主播连珠炮时块内多句）。
- 块是后续打标的单位（AI 不必逐句看 100+ 句）。

> 说明：若 AI 在阶段2 输出的是「句子级分段」，阶段3 可简化为「把 AI 段落直接映射为块序列」，自动执行即可。

### 阶段4：segmenter.py —— 切点吸附 + 时长约束（新增核心）
读取 `segments.json`（AI 边界主张）+ `transcript.json`（停顿数据），精修每个切点：

```
对每个语义边界 → 在边界期望位置 ±15s 窗口内找最近 ≥0.5s 停顿
   → 找到：切点挪到停顿中心 − 300ms（margin 防截字）
   → 找不到：切点保持（不动句边界），标 confidence=low 提示复核
时长兜底（脚本确定性执行）：
   - <45s → 并入相邻段
   - >10min → 按段内最长停顿强制拆分（拆分点标 low）
```

核心函数（参考 live-clip-tool 实现）：

```
_snap(cut, pauses, window=15, margin=0.3):
    在 pauses 中找 |停顿中心 - cut| ≤ window 最近者
    命中 → 返回 停顿中心 - margin
    未命中 → 返回原 cut（不动句边界）
```

> 段04 反例对照：当时 AI 边界落在 599500ms。若经过该机制，±15s 窗口内会吸附到 602975ms 附近的 4.7s 大停顿前（600 两侧完整句），话题「牛奶自嘲」就不会被切没。这正是该机制要消灭的故障模式。

### 阶段5：切割 + 封面（现有 cut_pipeline.py，已含 QSV 加速 + -ss 前置修复）
- 读取 `clips_refined.json` 直接切割，物理切点已是脚本精修结果。
- 输出目录维持现状：`output/{日期_原视频名}/{序号}_{标题}_{时间段}/`。

## 7. 决策点（实施前需确认）

1. **切点归属原则**：目前「过渡句归入后一段」仍由 AI 判断，吸附机制不动它，要不要把它也规则化（吸附时自动检测边界的过渡句位置）？—— 建议不自动化，保持 AI 判断，减少规则复杂度。
2. **margin 值**：参考值 300ms 是否够，需用真实整场跑一次按漏字率微调。
3. **是否需要五段式完整搬移**：本建议只引入「段3+段4」两个脚本环节，**不是**把 E:\live-clip-tool 的云端 LLM / 事件检测 / 代理视频等全量迁过来（避免范围膨胀、避免引入 DashScope 依赖）。

## 9. 验证结果（2026-08-08 完成，五轮全通过）

### 轮1 数据基础
`transcript.json` 全量 130 条静音：全部 ≥500ms；**≥1.5s 有 32 条**（占总静音 25%），作为锚点分布在各段边界附近，数据充足可吸附。

### 轮2 吸附算法原型
对现有 5 条真实段边界跑 `_snap(cut, pauses, window=15, margin=0.3)`：
- 段1→5 初/末吸附后：`0→93.31`、`163.76→462.11`、`462.11→629.76`、`629.76→708.01`，全部配平到停顿前。
- 修正规则：**首片 start 保持原封不动、末片 end 保持原封不动**（不再吸附成 0 或把片尾吃掉）。

### 轮3 锚点方案（重点）
尝试了两种"句间停顿"（≥0.5s 的 12 条句子空隙）太稀疏不能覆盖所有切点；**字符级静音 ≥1.5s（32条）作为锚点**才够用。引入吸附后安全校验：

```
boundary_unsafe(cut):
    若 cut 落入 [start,end] 且句子时长 ≤8s：→ 拒绝该切点（保持 AI 原值，confidence=low）
    若 cut 落入句子内部但邻近真实长静音（距离 <2.5s）：→ 可接受（confidence=high）
    否则：→ 高置信
```

段04 反例对照：AI 边界 `599.5s`（错误，切丢"自嘲"）在 ±15s 内无 ≥1.5s 静音锚点 → 拒绝并保持 low；段04 正确边界 `631.0s` 吸附到 `629.46`（4.7s 大停顿前）→ 高置信。**机制能区分"卫生问题"（吸附修复）与"语义错误"（拒绝+low）**。

### 轮3 完整 segmenter 流程（复用 live-clip-tool 验证）
用 live-clip-tool 的 `_apply_duration_rules + _refine_boundaries` 跑真实 5 条 segments：
- 输出 5 clip，时长为 93.1 / 70.4 / 298.4 / 167.6 / 78.3s，全部在 [45,900]s 内无需并入/拆分。
- 吸附后切点（93.31/163.76/462.12/629.76）vs 短句(`≤8s`)截断检查 → **0 处截断，全部高置信**。

### 5. 轮4 端到端（真实切割+重转写）
`ffmpeg` 按吸附后边界实际切段1(0.21-93.31) 与段4(462.12-629.76)，QSV 转 h264 后 FunASR 重转：
- 段1：13 句全为《食神》话题，首句前无截段、末句完整收于停顿；段周边界时间戳对齐（首句 70ms 起、末句 89.96s 止）。
- 段4：18 句全为 酒/优惠券/手表/运动/APP 话题，**首句前 2.1s 静音**（吸附生效无明显打断），末句自然结束。
- 未出现从当中切掉的情况，无缺漏字。

### 结论
五轮验证全通过。最终参数固化：

| 参数 | 值 |
|------|-----|
| pauses 阈值 | **≥1.5s**（字符级静音，非句间停顿） |
| 吸附窗口 window | ±15s |
| margin（切点=停顿中心-300ms） | 300ms |
| 短句拒绝阈值 | 目标切点落入 ≤8s 句内 → 拒绝 |
| 长句内静音接受阈值 | 距 ≥1.5s 静音 <2.5s → 接受 |
| 时长约束 | <45s 并入 / >900s 拆分 |
| 首尾规则 | 首段始点/末段终点不吸附 |
